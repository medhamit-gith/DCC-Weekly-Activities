Why a Cloudflare Worker?
  • Strava Club Activities API strips start_date from responses for privacy — no date on activities
  • Without dates, the app can't filter "this week" vs "last week" directly
  • Worker uses a fingerprint tracker: each activity is keyed by name|distance|movingTime
  • Activities are "first seen" timestamped when the cron first encounters them each week
  • Worker also acts as OAuth proxy — keeps client_secret off the device entirely
Why Two Auth Paths?
  • Strava OAuth: Full experience — personal analytics, radar charts, what-if engine uses real athlete ID
  • Club Code: Zero friction — members who don't want to connect Strava still see club data
  • Club code data source is identical (same Worker endpoint) — only profile fetch differs
  • Both paths require biometric lock (Face ID) after launch for device security
  • Valid codes: DCC2026, DESI2026 — stored in ClubCodeAuthService
End-to-End Data Flow
How activity data travels from Strava's servers to every chart and table in the app
1

Strava API — Club Activities Feed

The Cloudflare Worker's bot account calls GET /api/v3/clubs/212760/activities?per_page=200 using its own Strava access token. The response is an array of up to 200 activities, newest first. No start_date field is returned (Strava strips it for club privacy). Fields available: athlete name, activity name, distance, moving_time, total_elevation_gain, sport_type.

GET /clubs/212760/activities per_page=200 no start_date newest-first order
2

Worker — Fingerprint & Track (Monday vs Incremental)

Monday (UTC day=1): Full reset. Deletes all KV keys older than last week. Splits the 200-activity feed at position 50 (WEEKLY_ACTIVITIES_ESTIMATE): top 50 → this week tracker, rest → last week tracker. Assigns seenAt = Monday 08:00 UTC.

Tue–Sun: Loads existing tracker_YYYY-MM-DD from KV. Compares each activity's fingerprint (firstname_lastname|name|distance|movingTime). New fingerprints get seenAt = now. Already-seen fingerprints are ignored.

fingerprint = name|distance|movingTime KV: tracker_2026-03-16 WEEKLY_ACTIVITIES_ESTIMATE=50 Monday reset
3

Worker — Aggregate & Cache Payload

Iterates all tracked activities for the week. Groups by member name. Computes: totalDistance, totalElevation, totalMovingTime, rideCount, and weighted-average speed. Sorts members by distance descending. Writes the complete JSON payload to two KV keys: club_data_2026-03-16 (week-specific, TTL 7 days) and club_data (generic shorthand, TTL 7 days).

KV: club_data_2026-03-16 KV: club_data TTL 7 days sorted by distance
4

iOS — CloudDataFetcher.fetchData(weekOffset:)

Called from WeeklyDashboardView.loadClubActivities() whenever the user changes the week or the view appears. Requests GET /club-data?weekOffset=N. Decodes CloudDataResponse via JSONDecoder. Sets members: [CloudMemberData] on the shared singleton. Handles noDataAvailable: true for weeks with no KV data (past weeks that predate the tracker).

CloudDataFetcher.shared URLSession.shared.data(from:) JSONDecoder noDataAvailable flag
5

iOS — Convert to Activity Model

CloudDataFetcher.toActivities(weekOffset:) iterates each CloudMemberData and each nested CloudActivityData. Parses startDate (ISO8601 string from worker) if present, otherwise falls back to Wednesday of the target week as a stable midpoint date. Creates Activity instances with memberName, distance (km), date, averageSpeed, elevationGain, movingTime, type.

Activity struct ISO8601DateFormatter fallback: Wed of target week
6

iOS — Build MemberStats (Aggregation Layer)

Groups activities by memberName into a dictionary. For each member: sums totalKM, counts rides, averages speed, sums elevation. Looks up WeeklyCache.previousWeekLookup() (disk cache) to get last week's stats for trend calculation (TrendDirection.up/down/stable/new). Sorts by totalKM descending. Result: stats: [MemberStats] which all dashboard views consume.

MemberStats array WeeklyCache lookup TrendDirection sorted by km
7

iOS — Render in Dashboard Views

The AdaptiveDashboardRouter branches on horizontalSizeClass: compact → ProfessionalDashboardView (iPhone, 5-tab custom nav), regular → IPadDashboardView (iPad, Liquid Glass sidebarAdaptable). Both consume the same stats: [MemberStats], activities: [Activity], dateRange: DateInterval?, and athleteProfile: AthleteProfile props.

AdaptiveDashboardRouter horizontalSizeClass ProfessionalDashboardView IPadDashboardView
Authentication Architecture
Dual-path auth: Club code for casual members, Strava OAuth for power users
Path A — Club Code (Simple)
1

ClubCodeLoginView

User enters name + code (e.g. DCC2026). Shake animation on invalid entry.

2

ClubCodeAuthService.authenticate()

Validates against ["DCC2026","DESI2026"]. Saves to UserDefaults: dcc_club_code + dcc_member_name.

3

BiometricGateView

Face ID / Touch ID prompt. Required regardless of auth path. Skips Strava token refresh (no token exists).

4

Dashboard loads via CloudDataFetcher

No Strava token needed. Athlete profile is synthesised from club code member name.

Path B — Strava OAuth (Full-Featured)
1

UserAuthService.beginOAuth()

ASWebAuthenticationSession opens Strava. Redirect URI: dcc-activities://localhost/oauth/strava. 90-second timeout with fallback state reset.

2

handleRedirect(url:) → exchangeCodeViaProxy()

Extracts code= param. POSTs to Cloudflare /exchange. Worker proxies to Strava. Returns access_token + refresh_token + expires_at.

3

BiometricAuth saves tokens to Keychain

Access token → Keychain. Refresh token → Keychain. Both keyed under com.dcc.weeklyactivities service. Accessibility: WhenUnlockedThisDeviceOnly.

4

BiometricGateView + silent refresh

Face ID fires. If token stale (<5 min left), refreshAccessToken() calls /refresh on worker. Fail → force logout.

Member
Per-rider aggregated stats for one week
struct Member: Codable, Identifiable {
  let name:           String

  let totalElevation: Double   // metres
  let totalMovingTime: Int     // seconds
  let avgSpeed:        Double  // km/h weighted

CloudDataFetcher
@Observable — primary data service
  • Fetches /club-data and /club-data?weekOffset=-1
  • Decodes JSON into CloudDataResponse Codable
  • Persists to caches/ directory as JSON files
  • Loads cached data on cold launch (immediate UI)
  • Exposes: currentData, lastWeekData, isLoading, errorMessage
  • refreshData() triggers parallel async fetches
  • weekOffset parameter allows historical lookup
Key method: fetchClubData(weekOffset:) → async → sets @MainActor published state
UserAuthService
@Observable — Strava OAuth lifecycle
  • Builds Strava OAuth URL with client ID, scope, redirect
  • Handles dcc-weekly://oauth deep link callback
  • Calls Worker POST /exchange with auth code
  • Stores access/refresh tokens + expiry in Keychain
  • Calls Worker POST /refresh on expiry (5-min buffer)
  • logout() clears Keychain + UserDefaults auth flags
  • Exposes: isAuthenticated, athleteName, accessToken (computed)
Key method: handleOAuthCallback(url:) → async → calls /exchange → stores Keychain
InsightsViewModel
@Observable — analytics and chart data
  • Consumes CloudDataFetcher.currentData
  • buildMemberStats() → [MemberStats] sorted + ranked
  • computeRiderStats() → [RiderStats] with efficiency scores
  • weekOverWeekDelta() → comparison vs lastWeekData
  • topRider, totalClubDistance, avgSpeed computeds
  • Drives all chart data in InsightsView and AnalysisView
Key computed: memberStats: [MemberStats] — recalculated whenever currentData changes
ClubCodeAuthService
@Observable — first-layer entry gate
  • Validates user-entered string against hardcoded club code
  • Sets UserDefaults.isClubCodeAuthenticated = true on match
  • Exposes: isAuthenticated Bool
  • No network calls — entirely local comparison
  • Persists between app launches (UserDefaults)
Club code acts as a lightweight "members-only" gate before any data is shown.
BiometricAuth
LocalAuthentication wrapper — Face ID / Touch ID
  • Calls LAContext.evaluatePolicy(.deviceOwnerAuthenticationWithBiometrics)
  • Falls back to device passcode if biometrics unavailable
  • authenticate() → async → Bool (success/fail)
  • canUseBiometrics → Bool (checks LAContext.canEvaluatePolicy)
  • biometricType → String ("Face ID" / "Touch ID" / "Passcode")
  • Triggered on each app foreground if isBiometricEnabled = true
ClubDataService
Low-level HTTP helper for club data fetching
  • Constructs URLRequest for Worker /club-data endpoint
  • Handles URLSession data task with async/await
  • Returns raw Data for decoding by CloudDataFetcher
  • Throws typed errors: NetworkError, DecodingError
  • Used by CloudDataFetcher — not called directly by UI

CloudDataFetcher.swift Service Primary data service. Fetches /club-data for current and last week, caches to disk, provides currentData + lastWeekData to all VMs.
UserAuthService.swift Service Strava OAuth lifecycle: authorize URL, /exchange, /refresh, Keychain token storage, token expiry checks, logout.
ClubDataService.swift Service Low-level HTTP layer for Worker calls. URLSession + async/await. Returns raw Data to CloudDataFetcher for decoding.
StravaConfigModel.swift Config App-wide constants: clientID, workerURL, redirectURI, OAuth scope. Single source of truth for all Strava configuration.
DesignSystem.swift Config Spacing enum, color tokens, typography scales, animation presets. All UI uses these constants for consistent design language.
WorkerKVDashboardView.swift UI Admin sheet. Fetches and displays live KV cache state for current + last week. Shows per-rider distance, rides, speed, moving time. Accessible from profile menu.
RiderAnalysisView.swift UI Deep-dive sheet per rider. Activities list, performance radar chart, comparison vs. leader. Receives MemberStats as input.
PerformanceDashboardView.swift UI Debug/diagnostic sheet. Shows app memory usage, fetch timings, API latency stats. Accessible from profile menu.
CrashErrorView.swift UI Full-screen error recovery UI. Shown when critical data fetch fails. Displays error description + Retry button.
cloudflare-club-data-worker.js Backend Cloudflare Worker. Fetches Strava club activities, aggregates by member, caches in KV. Monday reset + 2-week bounded storage. Cron 3x/day.
cloudflare-workerworker.js Backend Cloudflare Worker. Stateless OAuth token exchange (/exchange) and refresh (/refresh). Holds STRAVA_CLIENT_SECRET.
